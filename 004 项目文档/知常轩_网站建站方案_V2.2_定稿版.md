## 执行摘要

知常轩是一个面向中小学生及家长的公益性文化传播网站，使命是**用底层逻辑和科学精神重新解读传统文化**，帮助青少年建立正确的世界观、人生观、价值观。

**核心差异化：** 不讲空洞口号，讲道理、讲逻辑、讲证据；传统文化与现代科学并重，贯通古今。

**内容模块：** 中国哲学 → 经典古籍 → 儒与道 → 书法文化 → 诗歌国度 → 近现代史 → 长征精神 → 当代科学（当前 8 个，数量不设上限，后续可动态增删）

**技术路线：** 延续现有 Flask + SQLite + Leaflet 技术栈，渐进增强，不推倒重来。

**上线节奏：** V1.0（结构上线）→ V1.1（首批内容可用）→ V1.2（互动功能）→ V2.0（一体化）→ V2.1（生态化）

### 1.2 设计总纲

- **色彩体系**：中国传统五色（玄青、缃黄、绛赤、翠青、霜白）为主调，辅以现代中性色
- **装饰语言**：中国传统纹样（云纹、回纹、祥云、缠枝、冰裂、梅兰竹菊），SVG 矢量实现
- **字体排版**：正文宋体/楷体，标题篆隶风格；移动端考虑系统默认字体可读性
- **整体调性**：典雅而不古板，厚重而有活力，适合青少年与家长共同阅读
- **无障碍**：符合 WCAG 2.1 A 级标准（字体可缩放200%、对比度≥4.5:1、键盘可操作）
- **移动端优先（新增，必须遵守）**：所有页面与交互改动必须考虑手机竖屏访问的缩放适配——viewport 正确、正文≥16px、点击目标≥44×44px、无横向溢出、375px 竖屏宽度下可用；任何改动上线前须在手机竖屏宽度下验证

## 二、视觉识别系统（VI）

### 2.1 中国传统色彩体系（统一色板）

| 色名 | 色值 | 用途 |
|------|------|------|
| **玄青** | `#1C1C2E` / `#0D0D1A` | 深色区块背景、页脚、长段落标题 |
| **缃黄** | `#E8C547` | 强调文字、高亮标签、重要提示 |
| **绛赤** | `#C73E3A` | 主按钮、印章、重要提示、长征/近现代史模块标识 |
| **翠青** | `#2D6A4F` | 科学/哲学模块主色、正确反馈、行动按钮 |
| **霜白** | `#F5F0E8` | 全站主背景（宣纸质感，不可或缺） |
| **月白** | `#E8EEF2` | 卡片背景、次级区块 |
| **墨黑** | `#1A1A1A` | 正文主文字（正文禁用纯黑#000） |
| **青瓷** | `#7BA3A8` | 次要文字、图标、装饰线 |

**配色比例参考：** 霜白/月白背景 60%，玄青/绛赤强调 30%，缃黄/翠青点缀 10%。

### 2.2 纹样规范（SVG矢量）

```
首页大图区：云纹 + 山水组合（低透明度，不遮文字）
模块标题栏：回纹边框（上下两条）
卡片内容区：细线分割（借鉴简牍样式，简约为先）
页脚：祥云纹 + 水波分隔
背景纹理：淡淡水墨山水或冰裂纹（透明度4-8%，实测文字可读）
栏目标签：方胜纹/如意纹
按钮四角：回纹微装饰
```

**实现规范：** SVG 内联或独立 .svg 文件；所有纹样有 `role="presentation"` 属性；文字区域留足白边（至少纹样宽度的1.5倍）。

### 2.3 Logo设计方案

```
主方案：以"知常轩"三字书法为核心
- 书体：篆书或隶书（体现厚重文化感）
- 辅助：红色印章（阳刻"知常"二字，朱文印）
- 可选英文：Zhichangxuan Academy（小字辅助）

使用场景：
- 深色背景：白色书法 + 红色印章
- 浅色背景：墨黑书法 + 绛赤印章
- 头像/小尺寸：仅印章（正方形，辨识度高）
- Favicon：印章简化版，16×16/32×32

禁止：书法加描边、加阴影、变形拉伸、添加3D效果
```

## 四、内容模块详细内容

> 每个模块说明：定位 + 色彩 + 栏目结构 + 首批内容（含ABC资源分级，对应资源盘点表）

### 4.0 模块页统一模板（内容板块结构）

> 所有模块页共用一套页面模板，由 8 个可选内容板块组成。板块按数据是否存在自动显隐；无数据的板块显示「内容筹备中 · 敬请期待」。新增模块只需在 module 表登记并配置板块数据，无需单独开发页面。

| 板块 | 说明 | 数据来源 | 阶段 |
|------|------|----------|------|
| 1. 文章 | 栏目文章列表 / 文章卡片（时间倒序，支持按栏目筛选） | article 表 | V1.0 |
| 2. 电子书籍 | 电子书（EPUB/PDF/在线阅读）书目卡片，可跳转网盘或在线阅读器 | ebook / resource_link 表 | V1.1 |
| 3. 图片资源 | 图片画廊（缩略图+原图分级加载），标注来源与授权 | media 表 | V1.1 |
| 4. 视频资源 | 原创/公有领域视频列表（不提供影视片段，合规红线见第九章） | video 表 | V1.2 |
| 5. 音频资源 | 经典原文真人朗读 / 原创音频播放器（TTS 规范见 7.5） | audio 表 | V1.0（道德经） |
| 6. 上传贡献 | 用户投稿入口（读后感/作品/资料），先审后发，未成年人内容需家长确认 | contribution 表 | V1.2 |
| 7. 评论及建议 | 评论/建议提交表单（昵称或匿名，不收集个人信息） | comment 表 | V1.2 |
| 8. 留言显示区 | 审核通过的留言/评论展示区 | comment 表（status=approved） | V1.2 |

**模板渲染规则：**
- 板块顺序固定：文章 → 电子书 → 图片 → 视频 → 音频 → 上传贡献 → 评论提交 → 留言展示
- 板块有数据才渲染完整区块；无数据渲染「内容筹备中」占位
- 模块页 Banner（定位+色彩+子应用入口）为公共头部，所有模块一致
- 特殊模块可附加专属区块（如儒与道挂载道德经 81 章在线阅读），以模板扩展形式追加，不另建页面

**数据模型扩展（按阶段实施）：**
- module 表新增 blocks 配置（JSON 数组，声明启用哪些板块）或独立 module_block 表
- 新增 ebook / video / audio / contribution / comment 表，沿用现有审核工作流（先审后发）

**科学辟谣方法论（必须遵守）：**

```
第一步：核实信息来源——是否来自权威机构/学术期刊/政府官网？
第二步：查证原文——谣言的原始说法是什么？是否被断章取义？
第三步：寻找反证——权威机构/学术共识怎么说？反对意见是否有证据？
第四步：解释原理——用受众能理解的语言说明为什么是谣言
第五步：给出替代——正确的知识是什么，而不是只说"这是错的"
第六步：注明参考——至少2个可靠来源，优先政府/权威机构/学术论文
红线：不扣帽子、不人身攻击、不情绪化表达
```

## 六、读书会社区（新增详细规划）

### 6.1 定位

读书会是知常轩的内容消费社区——让青少年创作、展示、互动，但**零商业化、零社交焦虑**。

**不同于普通论坛的设计原则：**
- 不设粉丝数/关注数显示（避免攀比）
- 不设点赞排行榜（避免刷屏）
- 不设评论区热度排序（避免引战）
- 青少年内容发布需家长确认

### 6.2 功能模块

| 功能 | 说明 |
|------|------|
| **读后感墙** | 学生投稿读后感/观后感，先审后发，展示不排序 |
| **少年诗社** | 学生原创诗歌展示（含古体诗/现代诗），按作者年级分组 |
| **书法园地** | 学生书法作品照片展示（收到即删原图，仅展示缩略图） |
| **每周一问** | 每周发布一个开放式问题（如"你觉得庄子的'子非鱼'论证有道理吗？"），学生匿名提交答案，志愿者精选展示 |
| **诗词接龙** | 异步诗词接龙游戏（不是实时对战，避免沉迷），每人每天限1次 |

### 6.3 防沉迷设计

```
- 无自动播放、无信息流无限刷

- 每周在线时长提示（非强制中断，仅提醒）
- 家长可查看共读记录（无详细行为数据）
```

### 6.4 实现阶段（V2.2 新增）

读书会全部功能归入 **V1.2 互动版**；V1.0 仅开放「读后感墙」投稿入口（先审后发，最小集）。避免首期开发摊子过大，把互动功能集中在合规框架齐备后再上线。

## 十一、运营与公益可持续

### 11.1 公益模式

```
短期（1年内）：纯公益
- 内容完全免费
- 资金：创始人个人投入 + 社会捐助（公开收支明细）
- 欢迎志愿者参与（给署名）

中期（2-3年）：部分自造血
- 图书/文创销售收入（知常轩笔记本/书签等，无暴利）
- 学校/机构定制内容（公益价格，非商业）
- 基金会赞助（申请公益创投/教育基金会）

长期（3年以上）：公益可持续
- 申请公募基金资格
- 面向公众透明募款
- 坚持内容完全免费
```

### 11.2 志愿者管理体系（新增）

**招募岗位：**
| 岗位 | 职责 | 要求 |
|------|------|------|
| 内容作者 | 撰写/编辑文章 | 有某一模块专业知识，文字表达能力 |
| 古文校对 | 核实古文原文/注释/译文准确性 | 汉语言文学/历史专业优先 |
| 科学审核 | 核实科学内容的准确性 | 理工科背景，能判断伪科学 |
| 设计志愿者 | SVG纹样/配图/版式 | 有设计能力，熟悉中国传统美学 |
| 技术志愿者 | 功能开发/Bug修复 | Python Flask开发经验 |

**管理规则：**
```
- 实名登记（身份证后4位+真名，隐私最小化）
- 不支付报酬（公益性质），给予署名+电子证书
- 签署简单合作协议（内容原创/不泄密/不商业化）
- 每季度公示志愿者贡献榜（经本人同意）
- 建立志愿者群（微信，仅工作沟通，禁止闲聊）
```

### 11.3 用户激励（轻量、非沉迷）

```
学习徽章：
- 「知常」徽章：完成任一模块入门篇（10篇阅读）自动获得
- 「日新」徽章：连续7天阅读每日一句
- 「小儒」「小道」「小诗人」等模块专属徽章

亲子共读打卡：
- 家长和孩子一起完成每日一句诵读
- 家长在打卡页点「已读」确认（非强制，无惩罚）
- 累计30天可获电子荣誉证书（可打印）

投稿入选：
- 学生作品被精选展示后，自动获得「小作者」徽章
```

## 十四、备份与灾难恢复（新增）

```
备份策略（每周执行）：
- 数据库：每日SQLite自动备份（.db文件压缩后上传至百度网盘）
- 静态文件：每周全量打包上传网盘
- 代码：GitHub/Gitee镜像，提交历史即备份

灾难恢复预案：
场景1：服务器硬盘损坏
  → 恢复时间：4小时（重装环境+从Git拉取+从网盘恢复数据库）
  → 预防：RAID1（已配置）

场景2：数据库误删/被黑
  → 恢复时间：1小时（从最近备份恢复）
  → 预防：每日备份+写保护

场景3：网盘账号被封
  → 备用账号：livejades@163.com
  → 紧急：72小时内切换所有分享链接

场景4：DNS污染/劫持
  → 监控：DNSPod免费监控
  → 备用：备案域名可切阿里云/腾讯云
```
