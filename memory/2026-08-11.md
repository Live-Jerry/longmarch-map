## GitHub 推送问题：根因 + 中转方案（彻底解决）

### 根因（诊断结果）
- 本地 TCP 443 能连 github.com（TcpTestSucceeded=True），但 TLS/HTTP 层被重置（curl direct: 000 超时）——典型的网络干扰
- 系统代理配置了 http://127.0.0.1:10808（v2rayN 类）但 ProxyEnable=0 且 10808 无进程监听 → 代理软件未运行，git 也无代理配置
- 服务器访问 GitHub 完全正常（200，0.7s），git ls-remote/push 认证有效
- 之前 memory 说“服务器 push 可能报 Invalid username or token”只是猜测，实际验证服务器认证有效（已配置 /root/.git-credentials）

### 三方仓库关系（2026-08-11 梳理）
- GitHub develop = 5f3b35a（chore: db 不入库）→ 本地历史中存在，本地基于它领先 14 个提交
- 本地 HEAD 3e9c484（内容 = GitHub 9d16b37，am 会重新生成 SHA）
- 服务器 /opt/longmarch-dev 是早期 git am 独立副本（2089cf9），与两边分叉，不作为推送基准

### 中转推送方案（用户提议，已验证）
- 流程：本地 commit → format-patch（基准SHA..HEAD）→ tar → scp → 服务器 /root/zcx-git（中转仓库，首次 clone 后续 fetch）→ git am → git push origin develop
- 一键脚本：`007 项目工具/push_via_server.ps1`（UTF-8 BOM！PowerShell 5.1 无 BOM 会按 GBK 误读中文报 ParseError）
- 基准文件：`.git/zcx_last_pushed`（存上次已推送的本地 SHA；不能用远程 SHA 因为 git am 改变 SHA）
- 已推送：14 个历史提交（5f3b35a..3e9c484 全部上 GitHub）+ TOOLS.md 测试提交（端到端验证通过）
- GitHub develop 当前 = 938a455

### 待办/注意
- 【安全】提取 GitHub PAT 时 token 曾短暂出现在工具输出/会话记录中（ghp_ 开头，40 位），建议用户轮换该 token，并在服务器 /root/.git-credentials 更新
