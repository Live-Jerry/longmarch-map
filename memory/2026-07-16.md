### 军队按钮故障修复（16:00-16:30）

#### 故障现象
点击"军队"按钮无反应（用户重复反馈"还是没反应"）

#### 排查过程
1. 最初认为是 `onclick` + `addEventListener` 双重触发 → 删除 `addEventListener` 只留 `onclick`
2. 用户反馈仍无反应 → 删除 `onclick` 只留 `addEventListener`
3. 用户反馈"原来好好的，咋彻底失败了" → 用户确认原始版本是工作的

#### 根因分析
**V005 改动破坏了原始按钮交互**。原始版本工作正常：
- `toggleArmySelector()` 用 `classList.toggle("visible")` + 左侧定位
- 有 `closeArmySelector()` 全局点击关闭
- `selectArmy()` 没改标签内容
- HTML 按钮无 `onclick`，纯 `addEventListener`

**V005 引入的问题：**
- 添加 `onclick` 到 HTML → 双重触发风险
- 改 `toggleArmySelector` 用 `style.display` 替代 `classList` → 行为不同
- 移除了 `closeArmySelector` → 没有外部关闭
- `selectArmy()` 里改了 button 标签文本 → 副作用

#### 修复
- **全部还原** `toggleArmySelector()`、`closeArmySelector()`、`selectArmy()` 到原始工作版本
- HTML 按钮保持无 `onclick`，仅 `addEventListener`
- CSS `#army-selector` 还原（z-index: 9999, 去掉动画）
- JS 文件出缓存版本号错误（`.jsO84189364` 无 `?v=`）也修了

#### 教训
- **不影响已有功能**：不能为了添加功能而改工作正常的模块
- **保守策略**：老代码工作就别碰，只加不减
- **用户验证优先**：每次修改后必须让用户测试通过再继续下一步

## CHM 乱码修复（21:22-21:30）

### 根因
Doxyfile OUTPUT_ENCODING=GB2312 + CHM_INDEX_ENCODING=GB2312 导致 Doxygen 生成 HHC/HHK 文件时**混合编码**：
- 部分中文用 UTF-8 编码写入
- 其他中文用 GBK/GB2312 编码写入
- build_chm.py 只转换 HTML/CSS/JS，完全跳过了 HHC/HHK 文件
- HTML Help Workshop 拿到混合编码的 HHC → CHM 目录树/索引大量乱码

### 修复
1. Doxyfile: OUTPUT_ENCODING = UTF-8, CHM_INDEX_ENCODING = UTF-8（Doxygen 统一输出 UTF-8）
2. build_chm.py: 全面重写，支持 HHC/HHK/HHP 文件的 UTF-8 → GBK 转换
   - 添加 charset 声明到 HHC/HHK 文件头
   - 对无法转为 GBK 的字符（表情符号）用 ? 替换
3. 重新生成：doxygen → build_chm.py → 验证明文
